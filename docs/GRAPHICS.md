# Graphics, upscaling and post-processing

This page records what the integrated engine actually does with the picture, which upscalers it runs itself, and the
status of the technologies that were evaluated but are not part of the renderer. It is written from the engine source
(`engine/fefw-recomp/runtime/src/gfx/`), its configuration reference (`runtime/docs/CONFIG.md`) and runs on the test
machine, not from vendor marketing.

## The pipeline

- The game's NVN calls are served by a host Vulkan 1.3 device (`src/gfx/nvn/`). NVN textures and buffers are backed by
  host memory, with block-linear untiling and GPU texture transcoding for BC and ASTC.
- The game's shaders are translated ahead of time to SPIR-V and cached in `work/shaders/spirv`; a new area's programs are
  compiled in the background, paced so the presented frame keeps the cores.
- The swap chain, present mode, HDR output and frame pacing are managed by `src/gfx/platform.cpp` and
  `src/gfx/play/play_display.cpp`. The launcher writes these settings and the engine's F1 page reads the same values.
- The 3D scene can render below the output size (`[upscale] scene_scale`, the launcher's picture size). The HUD and post
  effects stay at full size. That is the input the upscalers work on.

### Inputs available to a temporal upscaler

The engine can supply, per scene frame: colour, depth, camera motion vectors generated by the runtime from the game's
camera state, a Halton(2,3) sub-pixel jitter it adds when the game's own does not reach the G-buffer camera, exposure for
HDR, and temporal history. FSR 3 frame generation consumes that camera motion field; it does not need the game to provide
a separate full-screen vector buffer.

## What is implemented

| Technology | Where | Notes |
| --- | --- | --- |
| TAAU (built in) | `extras/taau.cpp` | Temporal reconstruction with the game's jitter, motion vectors and depth. Default for the NVN2 DLSS API. |
| AMD FSR 1 | `extras/fsr1_spatial.cpp` | Spatial, any GPU, sharpening 0 to 1. |
| NVIDIA Image Scaling 1.0.3 | `extras/nis_spatial.cpp` | Spatial, any GPU, up to 2x per side; FSR 1 is used beyond that. |
| AMD FSR 3.1 | `extras/temporal_ffx.cpp`, `ffx_files.cpp` | Temporal, through the FidelityFX API (SDK 2.4.0 Vulkan DLLs, or the 3.1 `amd_fidelityfx_vk.dll`). |
| NVIDIA DLSS / DLAA | `extras/temporal_dlss.cpp` | Through Streamline (v2.14.16 files), RTX hardware, quality presets or native AA. |
| Intel XeSS Super Resolution | `extras/temporal_xess.cpp` | Through `libxess.dll` (XeSS SDK 3.0.2), any GPU with DP4a, XMX on Intel Arc. |
| AMD FSR 3 frame generation | `extras/framegen_ffx.cpp` | Implemented and validated with FSR 3.1 on an RX 7900 XT: 60 rendered fps presented as 120 fps at 2560 × 1440. Requires `amd_fidelityfx_vk.dll` from FidelityFX SDK 1.1.4 and Vsync off. |
| Sharpening | `extras/extras_state.cpp` | FSR 1, NIS and FSR 3 sharpening, live from the Graphics page or F1. |

The vendor DLLs are not redistributed. The launcher's Graphics page lists the exact files each mode needs, searches for
them, and reports what is missing; a mode whose files or hardware are absent falls back with a reason in the log.

## Evaluated, not integrated

| Technology | Classification | Why |
| --- | --- | --- |
| AMD FSR Upscaling 4.x (ML) | Integrable later | The engine's FidelityFX path currently calls FSR 3.1 through the SDK 2.4 Vulkan loader. FSR 4 needs the newer entry point, its own input contract and a compatible device path; not attempted without a validated SDK and hardware to test on. |
| DLSS Frame Generation | Implemented, untested here | Streamline frame generation needs `sl.dlss_g.dll`, `sl.reflex.dll`, `sl.pcl.dll`, `nvngx_dlssg.dll` and `NvLowLatencyVk.dll`, an RTX 40 class GPU and hardware-accelerated GPU scheduling. The engine has the path and detects the files; this project has not run it on RTX 40 hardware. The validated AMD path is FSR 3.1 + FSR 3 frame generation. |
| XeSS Frame Generation | Not integrated | Separate SDK capability from XeSS Super Resolution; needs its own inputs and validation. |
| OptiScaler | Incompatible as designed | It redirects an upscaler interface a game already calls (DLSS/FSR/XeSS shims). This engine calls FidelityFX, Streamline and XeSS directly, so there is no vendor interface to intercept, and DLL replacement would be an unsupported hook. |
| ReShade | Optional external tool, launcher-managed | The Graphics page detects the 64-bit Vulkan layer in `%ProgramData%\ReShade`, checks this build's entry in `ReShadeApps.ini`, opens the official setup tool for `fefw.exe` with `--api vulkan`, and can disable the layer for this game only. ReShade is not bundled or silently installed. Its own overlay applies shaders on the presented swap chain; depth-dependent effects depend on the depth resources the engine exposes and are not guaranteed. |
| vkBasalt | Optional external tool, untested | Same reasoning as ReShade; a presentation-time Vulkan layer, no engine integration. |
| Other spatial sharpeners | Reusable only with a clean pass | The engine already has FSR 1 and NIS sharpening; a second post chain on top would duplicate work. |

## Licensing and distribution

- AMD FidelityFX SDK: MIT-style licence, but the Vulkan runtime DLLs are the player's to obtain; the release ships none.
- NVIDIA Streamline / DLSS: NVIDIA's SDK terms; the DLLs are the player's to obtain and must carry NVIDIA's signatures.
- Intel XeSS SDK: Intel's licence; `libxess.dll` is the player's to obtain, with the Visual C++ 2015-2022 runtime.
- ReShade: its own licence; it stays a separate download the user installs. EmblemWeave opens the official setup and never ships ReShade binaries or shader files.
- vkBasalt: its own licence; not integrated.

## ReShade (optional)

Verified end to end with the Add-on build of ReShade 6.8.0 and this build of the engine: the layer loads, the overlay
opens, and the launcher's switch keeps it out of the game process.

1. On **Graphics**, expand **ReShade (optional)** and press **Set up ReShade…**. Choose the official setup executable if the
   launcher does not find it in your Downloads or Desktop folder.
2. The setup opens with this build's `fefw.exe` and the Vulkan API already selected. Use the **Add-on** build when you
   want `.addon64` add-ons; choose the effect packs you want. Windows asks for administrator approval when the setup
   registers the Vulkan layer and writes `ReShadeApps.ini`. The same install from a console, with no window, is
   `ReShade_Setup_6.8.0_Addon.exe "<engine>\game-build\fefw\build\release\fefw.exe" --api vulkan --headless`.
3. Keep presets, `reshade-shaders`, and `.addon64` files beside `fefw.exe`. In game, press **Home** to open ReShade's
   overlay and select a preset. Effect packs come from the setup's download step; without them the overlay opens but
   has nothing to apply.
4. The **Load ReShade** switch on the same card only changes the game process: it sets the Vulkan loader's disable
   variables for this launch. It does not uninstall ReShade or affect other games. Use the setup tool to uninstall.

What the 6.8 setup writes, and what the launcher reads:

| Path | What it is |
| --- | --- |
| `%ProgramData%\ReShade\ReShade64.dll` and `ReShade64.json` | The layer and its manifest. The manifest is registered under `HKLM\SOFTWARE\Khronos\Vulkan\ImplicitLayers` and names `DISABLE_VK_LAYER_reshade_1` as its own disable switch. |
| `%ProgramData%\ReShade\ReShadeApps.ini` | The allowlist. Its `Apps=` value must contain this build's `fefw.exe`, or the layer is installed and never loaded. |
| `<build folder>\ReShade.ini`, `ReShade.log`, `ReShadePreset.ini` | This game's settings, its log, and its preset, written beside the executable the setup was pointed at. |

Two things in 6.8's own files would otherwise read as "broken" here, and both are handled:

* It writes a UTF-8 byte order mark before `Apps=`, so a parser that does not strip it sees `\u{feff}Apps` and reports
  *not enabled for this build* while the entry is right there.
* It writes `ForceShortcutModifiers=1` beside `KeyOverlay=36` (Home), which makes a bare Home key open nothing. The
  launcher sets that back to 0 when it starts the game and when the setup creates the file.

The proof it loaded is in `ReShade.log`: `Initializing crosire's ReShade version '6.8.0...' (64-bit) loaded from
'C:\ProgramData\ReShade\ReShade64.dll' into '...fefw.exe'`, then `Redirecting vkCreateSwapchainKHR` and `Recreated
runtime environment`. With **Load ReShade** off, the game starts normally and `ReShade.log` is not touched at all.

Depth-based effects depend on the depth buffer the engine exposes and are not guaranteed; colour, sharpening and
anti-aliasing effects do not need it.

## How to check a claim on your own PC

1. Set the mode in **Graphics > Upscaling**, start the game, and read `%APPDATA%\EmblemWeave\logs\engine-*.log` for the
   line naming the upscaler that ran, or the reason it was not used.
2. The engine's F1 page reports the same, plus `Files found` for the vendor DLLs.
3. `[upscale] mode` and its neighbours in `fefw.ini` are documented in `engine/fefw-recomp/runtime/docs/CONFIG.md`; the
   launcher writes the same keys, so a mode chosen in the launcher and in F1 cannot disagree.

## Known gaps

- FSR 3 frame generation is validated only on the RX 7900 XT (Adrenalin 26.10.1, FidelityFX SDK 1.1.4). Other AMD GPUs and drivers still need a run; DLSS Frame Generation is untested on RTX 40 hardware.
- ReShade's layer, allowlist, overlay and disable switch are verified (6.8.0 Add-on, Vulkan, this build). Individual shader packs and depth-based effects are not: they are the user's to choose, and depth-based ones may not see the buffers they expect.
- FSR 4, DLSS 4 and XeSS 3 features are not integrated.
- vkBasalt is not integrated.
- Performance numbers for each upscaler on this project's hardware are not yet recorded in a complete benchmark table; the
  FSR 3 frame-generation run above is a single validated result. The engine's own notes mention XeSS costing about 1.6 ms
  per frame more than TAAU on an RTX 4070 Super at 720p to 1440p; that is a single measurement from the engine's
  documentation, not a project benchmark.
