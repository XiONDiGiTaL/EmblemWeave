# Graphics, upscaling and post-processing

This page records what the integrated engine actually does with the picture, which upscalers it runs itself, and the
status of the technologies that were evaluated but are not part of the renderer. It is written from the engine source
(`engine/fefw-recomp/runtime/src/gfx/`), its configuration reference (`runtime/docs/CONFIG.md`) and runs on the test
machine, not from vendor marketing.

## The pipeline

- The game's NVN calls are served by a host Vulkan 1.3 device (`src/gfx/nvn/`). NVN textures and buffers are backed by
  host memory, with block-linear untiling and GPU texture transcoding for BC and ASTC.
- The game's shaders are translated ahead of time to SPIR-V and cached in `work/shaders/spirv`; a new area's programs are
  compiled in the background, paced so the presented frame keeps the cores.
- The swap chain, present mode, HDR output and frame pacing are managed by `src/gfx/platform.cpp` and
  `src/gfx/play/play_display.cpp`. The launcher writes these settings and the engine's F1 page reads the same values.
- The 3D scene can render below the output size (`[upscale] scene_scale`, the launcher's picture size). The HUD and post
  effects stay at full size. That is the input the upscalers work on.

### Inputs available to a temporal upscaler

The engine can supply, per scene frame: colour, depth, camera motion vectors generated by the runtime from the game's
camera state, a Halton(2,3) sub-pixel jitter it adds when the game's own does not reach the G-buffer camera, exposure for
HDR, and temporal history. It cannot supply motion vectors for this title's own FSR 3 frame generation, because the game
does not provide them and the runtime does not synthesise a full-screen field.

## What is implemented

| Technology | Where | Notes |
| --- | --- | --- |
| TAAU (built in) | `extras/taau.cpp` | Temporal reconstruction with the game's jitter, motion vectors and depth. Default for the NVN2 DLSS API. |
| AMD FSR 1 | `extras/fsr1_spatial.cpp` | Spatial, any GPU, sharpening 0 to 1. |
| NVIDIA Image Scaling 1.0.3 | `extras/nis_spatial.cpp` | Spatial, any GPU, up to 2x per side; FSR 1 is used beyond that. |
| AMD FSR 3.1 | `extras/temporal_ffx.cpp`, `ffx_files.cpp` | Temporal, through the FidelityFX API (SDK 2.4.0 Vulkan DLLs, or the 3.1 `amd_fidelityfx_vk.dll`). |
| NVIDIA DLSS / DLAA | `extras/temporal_dlss.cpp` | Through Streamline (v2.14.16 files), RTX hardware, quality presets or native AA. |
| Intel XeSS Super Resolution | `extras/temporal_xess.cpp` | Through `libxess.dll` (XeSS SDK 3.0.2), any GPU with DP4a, XMX on Intel Arc. |
| AMD FSR 3 frame generation | `extras/framegen_ffx.cpp` | Implemented, but requires the FSR 3 upscaler mode, which this title cannot use (see above). |
| Sharpening | `extras/extras_state.cpp` | FSR 1, NIS and FSR 3 sharpening, live from the Graphics page or F1. |

The vendor DLLs are not redistributed. The launcher's Graphics page lists the exact files each mode needs, searches for
them, and reports what is missing; a mode whose files or hardware are absent falls back with a reason in the log.

## Evaluated, not integrated

| Technology | Classification | Why |
| --- | --- | --- |
| AMD FSR Upscaling 4.x (ML) | Integrable later | The engine's FidelityFX path currently calls FSR 3.1 through the SDK 2.4 Vulkan loader. FSR 4 needs the newer entry point, its own input contract and a compatible device path; not attempted without a validated SDK and hardware to test on. |
| DLSS Frame Generation | Experimental, blocked | Streamline frame generation needs `sl.dlss_g.dll`, `sl.reflex.dll`, `sl.pcl.dll`, `nvngx_dlssg.dll` and `NvLowLatencyVk.dll`, an RTX 40 class GPU and hardware-accelerated GPU scheduling. The engine detects the files but has no verified frame-generation path for this title. |
| XeSS Frame Generation | Not integrated | Separate SDK capability from XeSS Super Resolution; needs its own inputs and validation. |
| OptiScaler | Incompatible as designed | It redirects an upscaler interface a game already calls (DLSS/FSR/XeSS shims). This engine calls FidelityFX, Streamline and XeSS directly, so there is no vendor interface to intercept, and DLL replacement would be an unsupported hook. |
| ReShade | Optional external tool, untested | A ReShade Vulkan layer can sit on the swap chain and apply its own effects. It is not bundled or auto-installed; depth-dependent effects would depend on the engine's depth resources being exposed to the layer, which is not verified. |
| vkBasalt | Optional external tool, untested | Same reasoning as ReShade; a presentation-time Vulkan layer, no engine integration. |
| Other spatial sharpeners | Reusable only with a clean pass | The engine already has FSR 1 and NIS sharpening; a second post chain on top would duplicate work. |

## Licensing and distribution

- AMD FidelityFX SDK: MIT-style licence, but the Vulkan runtime DLLs are the player's to obtain; the release ships none.
- NVIDIA Streamline / DLSS: NVIDIA's SDK terms; the DLLs are the player's to obtain and must carry NVIDIA's signatures.
- Intel XeSS SDK: Intel's licence; `libxess.dll` is the player's to obtain, with the Visual C++ 2015-2022 runtime.
- ReShade and vkBasalt: their own licences; if ever offered, they stay separate downloads the user installs.

## How to check a claim on your own PC

1. Set the mode in **Graphics > Upscaling**, start the game, and read `%APPDATA%\EmblemWeave\logs\engine-*.log` for the
   line naming the upscaler that ran, or the reason it was not used.
2. The engine's F1 page reports the same, plus `Files found` for the vendor DLLs.
3. `[upscale] mode` and its neighbours in `fefw.ini` are documented in `engine/fefw-recomp/runtime/docs/CONFIG.md`; the
   launcher writes the same keys, so a mode chosen in the launcher and in F1 cannot disagree.

## Known gaps

- No validated frame-generation path for this title.
- FSR 4, DLSS 4 and XeSS 3 features are not integrated.
- ReShade and vkBasalt are not bundled, tested or exposed in the launcher.
- Performance numbers for each upscaler on this project's hardware are not yet recorded in a benchmark table; the engine's
  own notes mention XeSS costing about 1.6 ms per frame more than TAAU on an RTX 4070 Super at 720p to 1440p. That is a
  single measurement from the engine's documentation, not a project benchmark.
