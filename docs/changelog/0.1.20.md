# EmblemWeave 0.1.20

> A package that packs part of its RomFS with zstd now plays without being repacked, and its compressed files cost 2 GB instead of a second copy of the game

## The crash two seconds after Play (#24)

A `.nup` can pack its files with zstd. A zstd entry is one frame for the whole file, with no way to seek into it, so the engine, which
serves the RomFS straight out of the package by offset, refused the package and the game broke on its first file:

```
fs: RomFS folder '...nup' cannot be served: main.npdm is compressed in the .nup
```

The refusal was the bug, in three places:

- **A compressed ExeFS no longer stops anything.** Those modules are loaded from the extracted `exefs` folder, so the package reader now
  lists them and carries on. Before this, a package whose only packed files were `main.npdm` and `rtld` was rejected outright.
- **The packed RomFS files are written out, once, and laid over the package.** The build writes exactly the entries that are packed (on the
  dump measured here, 65,074 files, 2.1 GB, not the whole 20 GB RomFS) into `engine\fefw-recomp\work\romfs-overlay`, and the engine reads
  those through the new `[fs] romfs_overlay` key. Everything else is still served from the package in place, so a packed game costs about
  2 GB of disk rather than a second copy of the game.
- **The build says what it is doing and the play button explains a build from before this release.** A game folder built by 0.1.19 still
  points at the package with no overlay: Play now says to press Build once, instead of the game dying on a break two seconds in.

## Verified

- The launcher wrote the overlay from a real 28.9 GB `.nup` (65,074 packed files, 2.1 GB) with `--unpack-romfs`, and the engine then booted
  that package with `romfs_overlay` set: `RomFS: 65074 of 252686 files are packed with zstd and are read from [fs] romfs_overlay`, the
  overlay merged 65,074 files, and the game reached its autosave screen with no break and no crash.
- `cargo build --release` and `cargo test -p emblemweave`: 118 passed, 0 failed.
- Not checked: a package whose RomFS is entirely packed, and a play-through past the first screen on one.

## Still open

The one case that still needs a repack by hand is a package that packs its RomFS in a codec other than zstd, which the launcher cannot read.
