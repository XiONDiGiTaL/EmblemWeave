# 0.1.39

## Launcher

- **Dumped add-on content is found and used.** Game Setup scans `dlc/<title id>/romfs` beside the ExeFS, RomFS or game
  root (or an explicit path), shows the packs on Setup and Overview, and writes the folder as `[aoc] dir` so the engine's
  `aoc:u` and `OpenDataStorageByDataId` serve them. An empty value is written when no packs exist. Add-on packages
  inside a `.nup` are unpacked once into a managed `dlc/` folder beside the copied ExeFS, with byte progress and
  cancellation; a marker reuses a finished unpack, and packs outside this game's add-on title-id block are ignored.
- **Updates install the release, not only the executable.** Overview now says **Update available** when a newer release exists,
  with the same **Update now** action on the notification and on About. The updater writes the new launcher, docs and engine
  sources over this install while keeping `data`, the built game, the fetched tools and third-party sources; `portable.txt` is
  never changed, so the storage mode stays as it was. If the running executable cannot be replaced, the old launcher starts
  and `logs\update.log` records why. An update from an older launcher that moved only its executable is finished from the
  download cache on first start, so those engine sources catch up without another download.
- **Import from folder…** now adapts to the folder it is given. The save folder, its `account` folder, an install folder above
  either, the title's own folder, a whole NAND save tree, and the contents of `000` without their parent all land in
  `account/DEFAULT_USER/000`, where the game reads them. A folder that holds no save is refused before the current save is
  touched, and an account folder whose save an older import left nested is found again. **Import profile** on the Saves page
  uses the same resolver, so an old save folder or a flat `000` folder becomes a profile that loads instead of one that fails
  verification later.
- The build toolchain is carried: clang-cl, lld-link, CMake, Ninja and an embeddable Python are downloaded into
  `engine/fefw-recomp/tools/bin` on first run (or with `EmblemWeave.exe --fetch-tools`), each archive checked against a
  pinned SHA-256 before it is unpacked. The Requirements page reports those four as **Carried**, and every probe and
  build step finds them before anything installed on the PC.

## Engine

- The frame rate counter can be hidden without a keyboard: hold one button of a pad pair and press the other. `[fps] combo`
  picks the pair — `l3_r3` (default), `minus_plus` for a handheld's Minus and Plus, `shoulders`, or `none`. The F1 page
  lists it under the counter's hotkey. Like `F2`, the press never reaches the game.
- `nxrt/platform.h` gained the host services (memory, threads, synchronisation, time, files) with a Windows and a POSIX
  backend, and the time subsystem moved behind it — phase 2 of `docs/LINUX.md`. On Windows the tick and the sleep are the
  same calls as before.

## ReShade

- Four presets and three filter shaders ship in `engine/fefw-recomp/reshade/`: **Vivid** (a little more saturation and
  contrast, deeper blacks), **Bright** (the same lift, lighter overall), **Game Boy** (four-shade DMG palette with ordered
  dithering) and **Retro CRT** (scanlines, aperture grille, glow, vignette). The effects are self-contained: they do not
  include `ReShade.fxh`, so they compile on a bare ReShade install with no shader repository.
- The Graphics page's ReShade drawer has a **preset picker**. Applying one copies the shaders and the preset beside
  `fefw.exe`, points `ReShade.ini`'s `PresetPath` at it and registers every preset for ReShade's own shortcuts, so **F3**
  and **F4** step through the looks in game and **Home** opens ReShade's overlay. `EmblemWeave.exe --apply-preset <name>`
  does the same from a console.
