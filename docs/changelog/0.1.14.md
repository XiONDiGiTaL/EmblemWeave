# EmblemWeave 0.1.14

The release that moved this history out of the README, and the one that proves the build repairs work instead of only
describing them.

## What's new

- **The changelog lives in `docs/changelog/`.** Every release keeps its own file, the README keeps a single link and a
  description of the current state, and the write-ups are shorter.
- **The two build repairs are tested end to end.** The retry loop was pulled out of the build step so it can be driven
  without a compiler: a `_deps` failure clears the fetched sources and retries exactly once, a stale `CMakeCache.txt`
  failure clears the cache and retries exactly once, a third failure is reported, and a failure that no repair matches is
  not retried at all.
- **The diagnostics section is tested against a log shaped like a real report.** A log with the error two thousand lines
  above CMake's summary produces the `first error in that log` section with the message, not the summary.
- **`--verify-log` now says when a repair applies.** On a log like the 0.1.11 report it prints the repair the launcher
  would attempt, so a pasted log and the launcher's behaviour can be compared directly.

## Verification

`cargo test -p emblemweave`: 88 tests. Both simulated logs were also run through the packaged binary: the reporter-shaped
log (no error line, `_deps` path in the tail) reports no error and names the dependency repair; the same log with a buried
`CMake Error` reports that error with its two following lines and the summary as the last line.
