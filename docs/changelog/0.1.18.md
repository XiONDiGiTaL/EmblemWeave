# EmblemWeave 0.1.18

> The build survives spaced and apostrophe folders, the pipeline stops opening hundreds of console windows, and the launcher finally has a portable mode

This release is the answer to the reports filed against 0.1.17. Every build failure in them has one of two causes, both
fixed here, and the two other defects the reports found are fixed as well.

## Build errors (#19, #22, #16, #18, #17, #11, #6, #3)

- **A cache wipe turned Release into Debug.** 0.1.17 set `CMAKE_RC_COMPILER` after `project()`. CMake then announced
  that its cache had to be deleted, configured again with its defaults, and the second pass picked the `clang++` driver
  in Debug instead of the `clang-cl` driver in Release. The first compiler call after that failed with
  `clang++: error: unknown argument: '-clang:-fmacro-prefix-map=…'`, and every report in the list above ends with that
  line. The resource compiler is now chosen before `project()`, the macro-prefix-map flag is chosen by driver, and
  `build_fefw.ps1` names `clang-cl` and `llvm-rc` by full path in the first configure so nothing changes after the cache
  is written.
- **Spaces and apostrophes are not a problem, and never were the reason for the errors.** A build from a folder with
  spaces in its name was run for this release: it configured `clang-cl`, Release, `llvm-rc`, compiled `fefw_obj` and
  linked `fefw.exe`. The shader translator is built from a staged copy rather than from the game's own folder, so an
  apostrophe in "Fortune's Weave" cannot reach MSBuild's path handling, which was the "cannot be created" error of
  0.1.16 and earlier. Non-ASCII folders work for the same reason, though an older release still fails in them.
- **Decoding no longer picks the Microsoft Store alias.** The launcher ran whatever `python` resolved to. On a PC without
  a real install that is the Store alias, which prints no version and opens the Store, and the decode stage reported
  only "the bridge reported an error" (#11). The launcher now asks each candidate for `--version` and uses the engine's
  own virtual environment first, then `py -3`, then `python`.

## The pipeline's wall of console windows (#23)

The compile stage starts one C compiler per shard. The launcher is a GUI program, so every compiler it started without
`CREATE_NO_WINDOW` opened a console of its own, and a large module is hundreds of shards: that is the thousands of blank
windows, and why they went away with the launcher. Every child the pipeline starts now sets the flag and inherits no
window. They were compiler processes throughout, not a shell, and the project contains no PHP at all; the troubleshooting
page now says that in as many words.

## Portable mode (#21)

An empty `portable.txt` beside `EmblemWeave.exe` moves `data`, `cache`, `logs`, `play` and `work` into a
`data` folder next to the program, so a release lives on one USB stick. Without the marker nothing changes. The
`About` page shows which of the two is in use.

## Smaller repairs

- `apply_patch.py` creates the directories a patch writes into and exits cleanly when a patch is already applied, which
  is what made the shader step fail on a second run.
- `control.nacp` is read as text rather than as a version number, so a dump whose package has it is not rejected.
- The `zstd` error no longer names a cache folder that does not exist.
- The haptics DLL is put beside `fefw.exe` before a launch, not only after a build, so updating the launcher does not
  drop rumble to the standard two motors (#10).

## Verified

- `cargo build --release` and `cargo test -p emblemweave`: 117 passed, 0 failed.
- Engine configure and build from a path containing spaces: `CMAKE_BUILD_TYPE` Release, `clang-cl`, `llvm-rc`, no
  "cache to be deleted" line, `fefw_obj` compiled, `fefw.exe` linked.
- The window flag is set on every spawn in `jobs.rs`; a full pipeline run was not watched for windows in this release.

## Still open

Native Linux and Steam Deck support (#7) is a port, not a repair, and stays requested. The save-file browser, the shader
compile cost on first entry to a new area, and per-game controller vibration are tracked in #10 and are the next work
rather than part of this release.
