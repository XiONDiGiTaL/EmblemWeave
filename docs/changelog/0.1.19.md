# EmblemWeave 0.1.19

> New areas compile about four fifths fewer shader parts, the compilers step aside when the picture is late, and a fresh copy keeps everything in its own folder

## First-entry shader cost (#10)

- **Shader parts are built when a draw asks for them.** The engine used to compile the shader parts of every program the game set, before
  any draw asked for them. In a measured session that built 2,975 parts and a draw took 341 of them: 88% of the work was for programs that
  were set and never drawn with. A program's parts are now queued when a command buffer is recorded with it, a few frames before the draw
  needs them. On the same route, part jobs per new program fell from 5.6 to 1.2 with the mean frame rate unchanged at 60.
- **The compile threads step aside when frames are late.** A new area sets hundreds of programs at once and each part is a driver compile
  that holds every core for tens of milliseconds, which is the processor peak that reads as the machine spiking. The background threads now
  sleep for up to `[nvn] compile_pace_ms` (default 8) after a part once presented frames are past `[nvn] compile_pace_after_ms` (default 20),
  so the frame in flight gets the cores back. Nothing is paced before the first frame, so the boot prewarm still runs flat out.

## Portable, without anyone having to find a marker file (#21)

- **A fresh copy keeps everything beside the program.** On its first start, when there is no profile folder yet, the launcher puts `play`,
  `work`, `save` and `logs` into `data` next to `EmblemWeave.exe`. Unzip it anywhere, carry it on a stick, and the saves and the build
  cache travel with it; no other copy on the PC sees them.
- **A copy already using the profile can switch from the launcher.** About now has a Storage section that names the folder in use, whether
  it is portable, and a button that turns it on: it writes the marker, creates `data` and copies your saves across. Restart to finish; the
  game is built into the new folder on the next build. Nothing is deleted from the old folders.
- Deleting `portable.txt` goes back to `%APPDATA%\EmblemWeave`.

## Verified

- `cargo build --release` and `cargo test -p emblemweave`: 118 passed, 0 failed, including the new switch test.
- A copy started with an empty profile folder wrote `portable.txt` and its `data` folder on its own, and the About page showed the new
  Storage section with the folder it was using.
- The two shader runs above were 100 seconds of the same scripted route on this PC. The GPU driver's own shader cache was warm for both, so
  the counts of part builds are the measurement; wall-clock milliseconds of compilation were not compared.
- The 32 ms worst frame in the demand-driven run (against 21 ms) is the cost of a part being built closer to its first draw; the runs also
  diverged, with the new default reaching 300 bound programs against 157.
