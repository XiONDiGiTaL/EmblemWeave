# EmblemWeave 0.1.37

> A guided first run, RomFS mods that stay above package data, faster lifted code, HDR UI brightness, and a broad engine update.

## A guided first run

The launcher now starts with a guided setup instead of a wall of controls. It validates the chosen game files, offers only the build tools that are actually missing, starts the first build, and confirms when the install is ready. The step is remembered, so closing the launcher during setup does not start it over.

The shell has been rebuilt around that flow: the lockup stays on the rail's true centre, recent activity folds into a fading hover panel fed by the bottom progress hub, and confirmations, profile prompts and upscaler dialogs all use the same modal frame. Save profiles now show the bundled protagonist portraits and allow a per-profile override.

The 0.1.36 UI details are also corrected: the folded settings drawers match the values the engine writes, the aspect label matches the setting in force, and the audio summary describes the buses the game will actually start with.

## Mods: the top layer is the mod again

RomFS mods could be silently undone when the game ran from a packed `.nup` or an archived `.nx`. The launcher writes packed files it cannot serve through the package into `work/romfs-overlay`; that folder was applied after the installed mods, so the game's original `GameData/Item.bin` replaced the mod's copy. The package data is now laid down first and installed mods last (#39). An overlay file that wins also clears the archived/packed source markers, so a replaced `.nx` or zstd-packed file cannot still read the old bytes.

The startup log names the layer that supplied a file, which makes a future report diagnosable instead of just "the mod does not work". The packed-`.nup` plus installed-mod ordering is covered by a regression test.

Patch-only mods are now supported. `.ips`, `.ips32` and IPSwitch `.pchtxt` files are installed like other mods, tied to the build ID of `main`, applied to the launcher's uncompressed copy before lifting, and guarded against conflicts and stale builds. A changed patch set makes Play wait for a rebuild. This support, previously described as unreleased in 0.1.36, is included here.

## Faster lifted code

The lifted game code is now compiled at `/O2` instead of `/O1`, which had been inherited from the original recompiler without tuning. In the measured Fortune's Weave scene the software-occlusion culler threads fell from 29–49% of a core each to 3–4%, the main thread from 4.5–5.8 ms to 4.1–4.2 ms per frame, and the whole process from 222–271% to 123–130% of a core. Render-thread time and the draw rate were unchanged. Existing `/O1` build folders migrate once; a build folder that should keep `/O1` can set `NX_OPT_PRESERVE=ON`.

The render thread also stopped reading the camera block back from the write-combined upload ring on every draw. With a temporal upscaler on, that readback was 59% of render-thread time in busy map scenes (13–23 ms per frame); the same scenes now spend 4–7 ms p50 and reach 60 fps with frame generation at 120.

## HDR: UI brightness separate from the scene

`[hdr] ui_nits` sets the white of menus, text, the HUD and 2D pictures in nits while the 3D scene keeps paper white. `0` is the previous behaviour. It applies live from Fortune's Weave's F1 menu and the generic play page, and the engine's own overlay follows it. The setting only acts on an HDR swapchain.

The split needs the scene's last pass before the UI, so the runtime scales that pass and leaves the UI at the requested white. Prewarmed pipeline keys now reject keys with alpha/gain fields; previously such a key could take a plain prewarmed pipeline with the unpatched fragment shader and the wrong layout. A depthless startup or title frame is treated as all UI so it does not stay at paper white.

## Engine update: fefw-recomp 0.2.1 and 0.2.2

The engine now carries the upstream 0.2.1 and 0.2.2 work: alpha testing (`[nvn] alpha_test`), the integer-texture shader fix on four more shaders, lean barriers on NVIDIA by default, texture uploads paced across frames with stand-ins, shaders kept in memory, burst threads for urgent pipeline parts, and the game's zstd multi-frame decoder running natively with the lifted implementation as fallback. The recompiler gained inline replacement, hot-callee inlining, NZCV in locals and related code-generation work, plus `wait_spin = auto` on eight or more physical cores. Controller paging menus show D-pad glyphs, and `fefw.exe --prepare-shaders` prepares the cache without starting the game.

Ultrawide displays keep wide one-edge pictures at 16:9, so the world-map art stays aligned with the markers and cursor drawn over it. The DLSS preset option now sets all six Streamline modes, including DLAA, instead of leaving the model to the driver. The launcher can also write a Low Memory graphics recommendation and restore it later.

## Reliability and diagnostics

- NX archives are validated against the current NXFormat specification, including application rows, before a build reads them.
- The engine builds from paths containing shell metacharacters, and the post-build copy no longer depends on a `cmd.exe` step.
- The Python probe recreates an environment that cannot start and reuses one that can.
- A freeze report includes the Vulkan budget, so a long-session stall has the numbers beside it.
- The save page stays inside a 1120-wide window.
