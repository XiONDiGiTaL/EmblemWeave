# EmblemWeave 0.1.36

> The GT tone map is recognised by every HDR hook, build-cache resets only fire on real CMake errors, an existing mod folder uses its absolute path, and advanced settings fold into drawers.

## HDR: the GT shader is recognised everywhere (#40)

0.1.35 added the Fortune's Weave GT tone-curve variant. The patch matcher found the shader and moved its `P` value to the display peak, but `hdr_is_tonemap` still tested only the older curve and LUT variants. A GT shader could therefore be patched while the temporal-upscale and scene-upscale paths classified it as an ordinary shader. The detector now tries the GT matcher too, so every HDR hook and the patch itself agree.

The new synthetic SPIR-V test builds a small GT-shaped module and checks that only its `P` load is wrapped in `FMax`, that the new result and constant IDs stay inside the declared bound and do not collide, and that a module missing a BT.2020 coefficient or a peak at or below 1.0 is left byte-for-byte untouched. It also asserts that the same synthetic module is now recognised by `hdr_is_tonemap`.

The runtime test passes. An HDR display and a real GT frame were not available here, so the visual result is not claimed.

## Mods: an existing folder now uses its absolute path (#39)

A game folder built by an older launcher can keep `mods = mods` in its `fefw.ini`. Starting it from another working directory then made the engine read a different folder, and RomFS mods appeared to be installed but never loaded. The build now writes the absolute mods path, and Play rewrites that key in an existing `fefw.ini` before launch. The Mods page names the folder the engine will read.

Code mods are still limited to a DLL or a `.sites` hook-site file inside `exefs`. An `.ips` or `.pchtxt` patch cannot apply to recompiled code, and the Mods page says so rather than pretending the mod loaded.

## Builds: only a real CMake cache is reset (#34)

The repair path for a build folder stuck in CMake's regeneration loop used to trigger on any log line containing `cache`. A shader-cache or texture-cache message could therefore delete the build configuration for no reason. It now requires one of the exact CMake markers (`CMakeCache.txt`, `CMake Generate step failed`, `build files cannot be regenerated`, and the matching loop messages). The regression test accepts those markers and rejects shader-cache and texture-cache lines.

## Also in this release

- **Upscaler search (#26).** The launcher also looks in an `upscaler` or `upscalers` folder from the game executable up through the engine checkout, so files left beside the source are found without moving them.
- **Paths containing `&` (#38).** The recompiler keeps its lifted sources inside the build tree when the checkout path contains an ampersand.
- **GPU counters.** An unimplemented counter is written once per address instead of repeating the same warning every frame.
- **Real `.xci` check.** The 29.2 GB retail card used for this check was read through its HFS0 root and `secure` partition, then refused at its first NCA because the NCA has crypto type 1. That is the intended result: retail cards are encrypted, EmblemWeave does not ask for keys, and a decrypted `.xci` or another plaintext package is required. No parser change was needed.

## Launcher polish

Advanced panels on **Graphics** and **Audio** now fold into drawers with a one-line summary: the shader-compilation controls show the current thread count and priority, **Upscaler files** shows how many of the three vendor sets were found, and the live “what the game will start with” panels stay closed until asked for. The drawer remembers its state while the page is open.

**Controls** draws ZL and ZR travel as filled bars instead of only numbers, so a trigger that stops short is visible at a glance. The existing custom sliders, buttons, status pills, frame-time graph and progress bars are unchanged.

The launcher was compiled, not driven through a screenshot pass, so the drawer's visual result is not claimed here.
