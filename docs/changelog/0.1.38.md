# EmblemWeave 0.1.38

> Save-profile corrections, a build fix when another Python's paths are inherited, and a rebuilt launcher.

## Save profiles: Global is data, not a slot

A profile that contains the game's `Global` data file was treated as if it held a broken save slot, so loading it stopped with `Global: not a Fortune's Weave save slot`. `Global` is the game's shared data beside the playthrough slots; it belongs in the profile and is still copied when the profile is loaded, but it is no longer validated, counted or listed as a slot. The empty-profile marker is ignored the same way in the current-save list (#48).

The save page also kept showing the previous profile as **Currently loaded** for a moment after a successful switch, because that frame had already been drawn with the old state. The page now uses the profile the load actually installed and asks for the next frame immediately, so the badge and the current-save section change together.

## Building when another Python's paths are inherited

On a PC with `PYTHONPATH` or `PYTHONHOME` pointing at another Python, the engine's Python 3.13 environment could load a 3.11 extension (`_socket.pyd`) during lifting and fail with `Module use of python311.dll conflicts with this version of Python`. The probe passed because it runs isolated, while the build inherited the variable (#43).

Every build step now removes inherited `PYTHONHOME` and `PYTHONPATH` and disables user-site packages, so the build uses only the engine's own virtual environment. The probe also imports `socket`, the module that exposed the conflict, and the launcher still recreates `tools\.venv` when that probe fails. No global Python needs to be uninstalled.

## Shader preparation

`--prepare-shaders` now keys its completion stamp on the content of the program list, not only its length, so replacing shaders with a different list of the same size cannot leave an old "complete" stamp trusted. A failed or cancelled run always replaces the stamp, so the next `--if-needed` run does the work again instead of skipping it.

## Verification

- `cargo test -p emblemweave`: **185 passed, 0 failed, 10 ignored**, including the `Global` profile regression and the inherited-Python-path regression.
- Reproduced the issue #43 failure with a Python 3.11 `_socket.pyd` on `PYTHONPATH`, then confirmed the same interpreter imports `socket` and `multiprocessing` after the launcher's environment is applied.
- Loaded two profiles from the save page and confirmed the **Currently loaded** badge and current-save slots update immediately after each load.
- Rebuilt the Windows launcher and the game engine from this tree.
