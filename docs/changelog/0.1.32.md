# EmblemWeave 0.1.32

> Code mods: a DLL in a mod's `exefs` now runs inside the game, and a mod can bring the hook sites it needs

A mod's `exefs` folder used to be a dead end: `.ips` and `.pchtxt` patches cannot apply to code that was compiled ahead of time, and
the Mods page said so. The third kind of mod, one that carries its own code, now has a place.

## What a code mod is

A DLL in `mods/<mod>/exefs/`, built against `engine/fefw-recomp/runtime/include/nxrt/mod_api.h`, the same interface ObeliskChamber
uses, so a mod written for either launcher works in both. When play mode starts the runtime loads every DLL of the enabled mods in
name order and calls its `nxmod_init`. From there a mod can hook the sites the game was lifted with, call the game's own functions,
run once per presented frame, give the game a function of its own to call (and lift the write protection of its constant data to
install it), and change the game's data files while the file system is being set up.

A mod that needs a site the game was not lifted with lists it in `exefs/<any name>.sites`, in the syntax of the engine's
`main.sites` with the kinds that add a call into the runtime (`inline`, `midhook`, `entryhook`) and one `@nsobid` line so sites
written for another version of the game are left out:

```text
@nsobid DB93B0125F4850601D61C3EDDE012F8EB2ECFE77
midhook 0x7100e1d03c      # comment
```

The launcher merges those lists with `main.sites` before the build and hands the result to the engine (`FEFW_SITES`), which lifts
`main` again when the list changes. Installing, updating or removing such a mod therefore asks for one Build the game; switching a
mod off does not, because a site with no hook attached only passes through. The build writes the list it lifted with next to
`fefw.exe` as `fefw.sites`, and the runtime checks every hook against it.

Loading can be turned off with `[fs] dll_mods = false`. A DLL runs with the same rights as the game, and the Mods page says so.

## The launcher

The Mods page lists code mods beside the RomFS ones, says when a mod's sites are missing from the built game, and has the button
that builds it again right there instead of pointing at another page.

## A `.nup` that packs its files plays as it is

The package reader refused a compressed entry, and the fallback was a folder of unpacked files that the launcher wrote before play.
The runtime now decompresses a zstd entry whole on its first read and serves its ranges from there (up to 1.5 GiB kept, then
dropped and read again), so a package that packs its ExeFS and RomFS is served directly: no repack, no unpacked copy, no
`svcBreak` two seconds into play (issue #34). An `[fs] romfs_overlay` folder still works and still wins over the package.

## A build folder `build_game.cmd` configured is reused

`build_game.cmd` passes `recomp\scripts\..\cmake\clang-cl.cmake` as the toolchain file, the launcher asks about
`recomp\cmake\clang-cl.cmake`, and the comparison between the two names did not resolve `..`: every start threw the folder away and
started the build from nothing. Both spellings now compare equal.

## Verified

- A `.nup` that packs 65,074 of its 252,686 files, played without any `romfs_overlay`: RomFS image of 252,686 files and 21,466
  directories, 25 s headless with 12,163 presents and 85 textures, no crash and no unreadable file (issue #34).
- A test code mod (`nxmod_init` plus a frame callback, built with clang-cl against `mod_api.h`): loaded from `mods/<mod>/exefs`,
  `nxmod_init` called, 30 frames seen, api version 3, main base as expected.
- The same test mod with a `.sites` file naming a site the build lacks: `mods: TestMod: 1 of its hook sites ... are not in this
  build: its hooks will not run. Build the game again.` and `mods: this build's hook sites: 33 (fefw.sites)`.
- `cargo build --release`, `cargo test -p emblemweave` (122 passed), and the whole engine built and linked with the loader in it.
- Not checked: a mod that hooks a site that is in the build (the test mod brings no hook of its own), a mod using `make_function`,
  `make_writable` or `edit_file`, and play through the launcher with the Mods page button.
