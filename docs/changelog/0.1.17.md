# EmblemWeave 0.1.17

> The black-screen release: the shader cache was half built, and nothing said so

- **Black picture with the sound playing, fixed.** Players running from a `.nup` got a window that stayed black
  while the music played (issues #12 and #15). The game was reading its assets from the package as it should; the
  shaders were the problem. The shader corpus is built by walking the RomFS folder, and a `.nup` is a file, so the
  walk found nothing and the corpus came out as only the shaders inside `main`: 151 cache records on the reporter's
  machine, where the game needs 12 088 blocks. Every scene program then had no translated shader, every draw was
  skipped, and the present pass copied an untouched texture to the window 60 times a second. **Build the game** now
  copies the shader archives (`*.bfsha`, `*.ptcl`, `*.arc`, `*.sarc`, `*.bnsh`, about 1.4 GiB) out of the package
  once, builds the corpus from that folder, and remembers which folder each corpus came from, so one built from a
  path that is not it is rebuilt instead of reused.
- **A half-translated cache is repaired, not called translated.** The build used to skip the shader step when any
  `.spv` existed. It now compares what the corpus expects (`corpus/unique.tsv`) with what the translator reported
  (`spirv/results.tsv`, written only when a run finishes), translates just the missing blocks with the harness's new
  `--only-missing`, and merges each run's report instead of replacing it. A cache with a few files and no
  `results.tsv` is a translation that was interrupted, and that is what it reports now.
- **The engine says which GPU it picked, and when a frame reached the screen.** The GPU lines carry vendor and
  device ID and the driver version decoded from Vulkan's packed form; `first frame presented: 1280x720, format 44,
  present mode immediate, frame 1` is logged once, at the present that succeeded. A present that failed is no longer
  counted as a frame on the display, `VK_ERROR_DEVICE_LOST` is named on acquire, submit and present, and the out of
  date and surface lost results say what they mean.
- **One error instead of 598 warnings.** A program whose shader was never translated used to log a warning per
  program: 598 of them in the reporters' logs, each true, none of them saying what they added up to. The first eight
  are still listed by block hash, then the engine states the consequence once: every draw belonging to them is
  skipped, the window shows only what the last clear left, and the SPIR-V folder it looked in is named. The shader
  cache now records its folder even when `results.tsv` is missing, which is the case that printed an empty path.
- **A rendering test that reads the picture back.** The graphics tests gained
  `presents_a_known_colour_and_reports_the_first_frame`: a 320x180 window, eight frames, a screenshot at the fifth,
  and then the pixels themselves, because a present that returns `VK_SUCCESS` is not a frame on the screen. It fails
  on `presents != 8`, on a failed present, on device loss, on a validation error, and on a mean channel of 2 or less
  (the scene clears to about 13, 20, 36), so a black window fails it. It runs without the game, like the rest of
  `nxrt_gfx_tests`.
- **The zip is written entry by entry, and checked before it is published.** The old packaging handed the folder to
  a compressor, which is how a Windows build produces names with backslashes and, on Linux, one flat pile of files.
  `tools/package_release.ps1` now builds every entry with forward slashes inside the same `EmblemWeave-vX.Y.Z/`
  folder every release has extracted to, writes the folder entries, keeps the executable bit, and runs the new
  `tools/verify_archive.py` against the file it just wrote. The verifier refuses
  absolute paths, drive letters, `..`, `./`, backslashes, control characters and case-colliding duplicates, checks
  that the files the launcher reads are at their paths, and with `--extract` unpacks the archive and checks nothing
  landed outside its folder. `tools/release.ps1` runs it again over the assets and compares their hashes with the
  manifest before `gh release`. Verified: 1287 files in 131 folders, no backslashes, no absolute entry, and the
  same tree from `unzip` and from Python's `zipfile` under Ubuntu; the translator tarball extracts with
  `-rwxr-xr-x` and its ELF binary prints its usage. One real bug came out of it: `docs/PACKAGE.md` was landing in
  the zip's root, not in `docs/`.
- **Builds from the zip get past CMake again.** The release package excluded every folder named `third_party`,
  which took `runtime/third_party` with it: dav1d, FSR 1, NIS, Streamline and the ffx API. Every build from a
  download then stopped at `add_subdirectory given source .../runtime/cmake/../third_party/dav1d which is not an
  existing directory`, and downloading dav1d by hand did not help unless it landed exactly there (issues #16 and
  #17). The two fetched trees (`tools/textures/third_party`, `tools/shaders/third_party`) are now named
  individually and the runtime's own is shipped, so the zip goes from 1287 to 1480 files. The verifier requires
  `runtime/third_party/dav1d/CMakeLists.txt` from now on, and the engine's `media_deps.cmake` builds without the
  AV1 movie decoder, with a status line, if a tree genuinely lacks it, instead of failing the configure.
- **The launcher compiles for Linux, and says so before it refuses.** Every operating-system fact now comes from
  one module (`platform.rs`): whether the game is running, whether this system may install build tools, whether it
  can build the game, where the launcher's data lives, and what the platform is called. Off Windows the installer
  and the build refuse with a sentence naming the platform and pointing at [docs/LINUX.md](../LINUX.md), instead of
  running `winget` and a `vcvars64.bat` that are not there. `cargo check -p emblemweave --target
  x86_64-unknown-linux-gnu` exits 0, which is a compile and not a claim that the game plays there: Linux, SteamOS
  and the Deck have a documented plan with the phases that were actually run marked, and native Linux support is
  not advertised. [docs/PLATFORMS.md](../PLATFORMS.md) is the audit of the 69 files that include `<windows.h>`,
  the 28 `Command::new` call sites and what each one needs on another system.
- **Saves load, and profiles can be renamed and copied.** Loading a profile wrote it into the first account folder
  by name, and the engine names that folder after the save's owner: with more than one present (its built-in user,
  a console user id, a folder an earlier import left empty), the profile went where the game never looks, which is
  why loading appeared to do nothing. The launcher now reads and writes the account folder the game last wrote. The
  Slots list shows each slot's size and the save it belongs to, and moves a slot to `backups/` so the game offers
  a new game there again. Profiles take a name and can be renamed (the folder moves) or copied (a branch of the
  story), and Remove still moves rather than deletes.
- **Vibration reaches the game.** The Controls page's Vibration slider was kept in the launcher's own config and
  never written where the engine reads it, so the pad never shook (issue report: it did on the gold disc). Rumble
  is now a switch (`[pad] rumble`) and a strength (`[pad] rumble_scale`, 0 to 100 %), read from and written to the
  game's `controls.ini` like the dead zones, seeded from the launcher's saved value when the file has none.
- **A graphics menu with the settings the engine actually has.** The Rendering section gained the temporal
  upscalers' quality preset, the game's own scene scale, frame generation (DLSS or FSR 3), what replaces the
  game's console DLSS calls (TAAU, DLSS, FSR 3 or bilinear), texture compression quality and the GPU choice. Each
  one is written to the engine's own keys (`[upscale] quality`, `scene_scale`, `[dlss] frame_gen`, `upscaler`,
  `[display] astc_quality`, `[gfx] gpu`), and a change made in the game's F1 menu is taken back onto the page.
- **Shader compilation has a CPU dial.** While a new area loads, the engine compiles shader parts and whole
  pipelines on background threads; its default is `min(4, cpus / 6)`, below normal priority, in Windows'
  efficiency mode, which on a 24-thread laptop is still four threads at the top of the boost table (reported: CPU
  clock at 6 GHz while shaders compiled). The new Shader compilation section caps that thread count and sets its
  priority to below normal, normal or idle, and can switch the efficiency mode off; the values go to `[nvn]
  gpl_threads`, `compile_priority` and `compile_eco`, and are left alone at Automatic.
