# EmblemWeave 0.1.22

> Play prepares a packed package and starts the game itself, so nobody has to know about the check first

## Play does the check

A `.nup` that keeps some of its files packed with zstd cannot be read in place, and 0.1.21 put the repair behind a button on Game Setup.
That still asks the player to know which button to press, and a game folder built by an earlier release fails the moment they press Play
instead.

Play now does it on its own:

- If the built game points at a package whose files are packed and no overlay is recorded, Play starts the same check, keeps a note
  that a game was asked for, and starts the game the moment the files are written. The status bar and Diagnostics show the writing.
- Pressing Play again while that check is running does not write twice: it waits for the run already going and starts the game after it.
- If the check fails, the waiting game is dropped and the failure is shown, rather than a game starting from a half-written folder.
- A package that is read in place, and every ordinary dump, goes straight to the game as before.

**Check my game folder** on Game Setup stays, for anyone who wants to prepare the folder without starting the game.

## Verified

- `cargo build --release` and `cargo test -p emblemweave`: 119 passed, 0 failed.
- Not checked: a press of Play on this machine against a packed package with no overlay, end to end. The check it starts is the one
  measured on a real 28.9 GB `.nup` in 0.1.20 (65,074 files, 2.1 GB, engine booted from the package with the overlay), and the
  condition that triggers it is the same one the engine logs as read.
