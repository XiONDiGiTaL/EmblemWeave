# EmblemWeave 0.1.25

> The Graphics page now shows which upscaler files are on disk, where they go, and can find them for you

## Upscalers and frame generation (#26)

FSR 3.1, DLSS and XeSS all need DLLs their vendors do not let us ship. Without them the engine falls back to its own temporal upscaler
(TAAU) and frame generation does not start, which is what the F1 menu reported: `Files found: DLSS no, DLSS-G no, FSR 3 upscaling no, ...`.
The exact folder to put them in was only in a tooltip, and the launcher did not look in the same places the engine does: `upscalers\fsr`
was searched by the engine and `upscalers\fsr3` by the launcher, so following the old hint could change nothing.

Graphics has an **Upscaler files** section at the top:

- One row each for FSR 3.1, DLSS and XeSS, saying where the files were found or exactly which files are missing. FSR 3 frame generation is
  named separately because it needs the v1.1.4 `amd_fidelityfx_vk.dll`, which the v2.4 loader pair does not include; the same for DLSS
  Frame Generation's five extra Streamline files.
- **Open the upscalers folder** creates `%APPDATA%\EmblemWeave\play\upscalers\{fsr,streamline,xess}` and opens it.
- **Look for the files** searches the launcher's folder, the engine folder, Downloads and the Desktop one folder deep, copies what it finds
  into that folder, and reports what is now ready and what is still missing. Running it twice copies nothing the second time.
- The same search runs headless with `EmblemWeave.exe --adopt-upscalers`, for a support report.

The launcher also looks in the engine folder and the run folder for both `upscalers\fsr` and `upscalers\fsr3`, which is where a copy made
into the package by hand now lands, and it passes `[upscale] xess_dll` as well as the FSR and DLSS paths to the game. XeSS is in the
Upscaling list and in the DLSS replacement list, so the engine's own XeSS support can be chosen from the launcher.

## A build from an older release (#24, reported again on an old build)

The engine is compiled from the sources in your copy, so a new launcher beside an old build keeps running the old engine, which is how the
packed `.nup` crash from #24 came back in a report after it was fixed. The build now records `[engine] built_by` in `fefw.ini`, and
Overview says `This game folder was built by an earlier release; press Rebuild to update its engine to 0.1.25` until it does.

## Verified

- `cargo build --release` and `cargo test -p emblemweave`: 119 passed, 0 failed.
- The Upscaler files section was seen on the running launcher in both states: three missing rows with the folder path and the two
  buttons, and three found rows after DLL-shaped files were placed in the run folder's `upscalers` (FSR 3.1 without frame generation,
  DLSS with it, XeSS).
- `--adopt-upscalers` was run against a fake Streamline set in `Downloads\test-upscaler-sdk`: it copied four files into
  `play\upscalers\streamline` and reported `found: DLSS; missing: AMD's FidelityFX DLLs`.
- The Overview line was seen on the running launcher against a game folder with no `built_by` stamp.
- Not checked: real AMD, NVIDIA and Intel DLLs (none are installed here), and a game start that uses them.
