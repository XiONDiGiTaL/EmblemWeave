# EmblemWeave 0.1.35

> Plaintext `.xci` game cards now build alongside `.nup`, `.nsp`, `.nx` and extracted dumps. The `.nx` and CMake fixes from 0.1.34 get named regression coverage, and encrypted retail cards are refused by name instead of being copied as garbage.

## Plaintext `.xci` game cards

**Game Setup > Choose package…** now accepts a plaintext `.xci`. EmblemWeave reads the card header, walks its HFS0 root, opens the `secure` partition and unpacks the program and control NCAs into `work\xci\<title>-<bytes>`. From there it is the same path as an `.nsp`: the game boots from the unpacked ExeFS and RomFS, the recompiler reads the same files, and the existing `dump.txt` cancellation and reuse rules apply. Nothing in the image is rewritten.

A retail cartridge stays encrypted. Its NCAs carry a non-zero crypto type and need the console's keys, which this project neither ships nor asks for. The Game Setup check names the first encrypted NCA it finds; it does not unpack it, and it does not pretend the card is unsupported for any other reason. Use a decrypted `.xci` made from your own dump, a plaintext `.nsp` or `.nup`, or an extracted folder.

The reader is in `crates/ew-format/src/xci.rs`. It reuses the plaintext NCA parser and unpack code that the `.nsp` path already used, so a change to section offsets or RomFS walking cannot fix one container and silently leave the other behind. Synthetic tests cover the HFS0 entry layout, the root-to-`secure` nesting, a bad magic, and the encryption refusal. There was no real `.xci` in this repository to test, so an end-to-end run from a cartridge image is not claimed here.

## The `.nx` and CMake reports (#28 and #35)

Both behaviours shipped in 0.1.34: the `.nx` archive is read through NXFormat and materialised for the engine, and the build's version reader accepts CMake prereleases such as `4.5.0-rc3`. This release adds a named regression for the `.nx` picker path, so issue #28 cannot regress into a folder-only search without a test failure, and keeps the CMake prerelease test beside the parser comment that names issue #35.

The `.nx` test uses the checked-in NXFormat fixture and asserts that Game Setup opens it as a package. The CMake test checks `4.5.0-rc3`, `4.4.4,` and `v1.13.2` against the leading-number reader.

## Verification

- `cargo test -p emblemweave -p ew-format`: 140 launcher tests passed, 10 ignored; 24 `ew-format` tests passed, 2 ignored; both NUP fixture tests passed.
- New `.xci` parser tests: HFS0 entries and offsets, card header and secure partition nesting, plain-file rejection, encrypted NCA refusal.
- `cargo check -p ew-format -p emblemweave` passed.
- Not checked: a real `.xci` image, and an end-to-end build from one. The parser is tested against synthetic HFS0 layouts; a retail card is expected to be refused because its NCAs are encrypted.
