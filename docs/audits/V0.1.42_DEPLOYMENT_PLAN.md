## 2. Backup strategy for the actual deployment

1. Create a fresh timestamped directory `E:\EmblemWeave_backups\pre-v0.1.42-deploy-<YYYYMMDD-HHMMSS>`.
2. Copy `data\config.json`, `data\play\*.ini`, `data\engine.txt`, `portable.txt`, `data\save` (including
   `backups`), the mods folder, `data\logs` and `data\reports`.
3. Copy the current `EmblemWeave.exe` and `data\play\fefw.exe` so the previous binaries are recoverable even if
   the launcher's own "Old versions" folder is lost.
4. Write `SHA256SUMS` for every copied file and verify it before deploying.
5. Do **not** copy the shader cache, work directory, RomFS overlay or the external game data. Record their paths
   and sizes instead.
6. Confirm the save count and profile count match the pre-deployment inventory before proceeding.

## 3. Deployment manifest

### Replace (application-owned)

| Path | Source | Rule |
| --- | --- | --- |
| `EmblemWeave.exe` | canonical release build | Replace only after hash matches the release manifest |
| `docs\` | release docs | Replace tracked guide pages; keep user-created files |
| `upscalers\ffmpeg\*` | release package | Replace DLLs and `SHA256SUMS`; hashes must match |
| `tools\` | release package | Replace offline verifiers |
| `engine\fefw-recomp\` tracked source and docs | canonical archive | Replace source only; never delete `work\`, `game-build\` outputs or mods |

### Retain (never overwritten automatically)

```
portable.txt
data\config.json
data\engine.txt
data\play\fefw.ini
data\play\controls.ini
data\save\**                     (saves, profiles, backups)
data\logs\**
data\reports\**
data\work\**                     (decoded data)
engine\fefw-recomp\work\**       (shader cache, RomFS overlay)
engine\fefw-recomp\game-build\** (build outputs until a deliberate rebuild)
mods\** and any mod configuration
```

### Create

- The timestamped deployment backup directory.
- `data\reports\v0.1.42-deployment.txt` recording source commit, artifact hashes, operator, time and result.
- A post-deployment diagnostic report after the smoke test.

### Migrate

No configuration migration is planned. `save_dir` already points at the portable save folder and
`paths.game_root` already points at the `.nup`. The launcher's `sync_save_dir` must be allowed to reconcile the
INI at startup; it must not rewrite the folder to the launcher directory.

### Must never be overwritten

- Any file under `data\save` other than files the launcher itself creates during normal play.
- `portable.txt`, `data\config.json`, `data\engine.txt`, `data\play\fefw.ini`, `controls.ini`.
- Mods and their configuration.
- External game data.
- The pre-deployment backups.

## 5. Deployment procedure (when authorized)

1. Stop the launcher and any running `fefw.exe`.
2. Create and verify the fresh backup as in section 2.
3. Record pre-deployment hashes of `EmblemWeave.exe`, `data\play\fefw.exe`, `config.json`, `fefw.ini` and
   `engine.txt`.
4. Replace only the application-owned paths in section 3. Do not mirror a directory tree over `E:` and do not
   delete unknown files.
5. Verify every replaced file against the release manifest SHA-256.
6. Launch the launcher. Confirm version 0.1.42 and engine detection.
7. Run the checks in section 7.
8. Write the deployment record and a diagnostic report.

## 6. Rollback

Trigger rollback if the launcher fails to start, the engine is not detected, saves are not discoverable, or the
runtime crashes before the first frame.

1. Close the launcher and `fefw.exe`.
2. Restore `EmblemWeave.exe` and `data\play\fefw.exe` from the fresh backup.
3. Restore `data\config.json`, `data\play\fefw.ini`, `data\engine.txt` and `portable.txt` only if they were
   changed.
4. Restore `data\save` from the backup only if the launcher wrote or migrated anything unexpectedly; compare
   file counts first.
5. Re-verify the restored hashes against the backup `SHA256SUMS`.
6. Relaunch and confirm the previous version works. Keep the failed deployment's logs.

The launcher's own "Old versions" folder is a second line of defense, not a substitute for the backup.

## 7. Post-deployment checks

- [ ] Launcher version and About text show 0.1.42; the Buy Me a Coffee link appears only in About.
- [ ] Engine is detected and the game-data verdict is OK/Warn with the expected game root.
- [ ] Portable paths resolve under `E:\EmblemWeave\data`, not the launcher directory.
- [ ] `save_dir` remains `E:/EmblemWeave/data/save`; profiles 1 and 2 and all 96 saves are visible.
- [ ] Start the game, reach the first frame, and confirm logging continues with the debug console hidden.
- [ ] No unexpected console window appears during build or launch.
- [ ] Create a save, close, restart the launcher and game, and confirm the save is listed.
- [ ] Create a diagnostic report; verify the ZIP opens, contains config, logs and the newest engine log, and its
      SHA-256 matches the handoff panel.
- [ ] Repeat a menu-to-title transition several times.
- [ ] Exit and confirm the display returns to its original mode/HDR state.
- [ ] Confirm rollback files are still present.

Until these checks pass, the E: deployment is **not** ready and v0.1.42 must not be published.

## 8. Current blockers

1. FCC's engine changes are uncommitted; a clean production runtime cannot be built from `main` yet.
2. The installed runtime is older than the newest engine build and neither is canonical.
3. #41 has no implementation, and #79 has no field confirmation after the 0.1.42 fixes.
4. No v0.1.42 release zip exists yet; `docs/release.json` correctly still says 0.1.41 (unreleased).
5. Engine test baseline has 14 documented failures whose classification is only partly defensible.
